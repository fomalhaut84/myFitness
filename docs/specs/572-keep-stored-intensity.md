## 1. 배경
강도 라벨 보정은 역치 (심박 = LTHR · 파워 = 역치파워) 를 쓰고, 역치가 바뀌어도 과거 값은 다시 계산하지 않는다 (#570 스펙 §2-5). 그런데 일일 cron 은 최근 30일 활동을 다시 받아 upsert 하면서 **현재 역치로 다시 분류**했다 → 최근 30일만 새 역치, 그 이전은 옛 역치로 섞인다. 심박 기준도 M4-5 부터 같은 동작.

## 2. 요구사항
- [x] F1 `keepStoredIntensity` — upsert update 에서 기존 행에 값이 있는 기준 (심박 `intensityLabel` · 파워 `powerIntensityLabel`) 의 4개 필드를 뺀다. 새 활동 · 빈 기준은 지금처럼 계산
- [x] F2 예외: 러닝 외로 종류가 바뀐 활동의 파워 값 비우기 (#575) 는 유지
- [x] F3 다시 분류 경로 = `scripts/backfill-intensity.ts --force` (심박 전부 + 파워 `fillMissingPowerIntensity({ force: true })`)
- [x] F4 페이지 단위로 기존 라벨 1회 조회 (활동마다 조회하지 않는다)

## 3. 결과 · 대가
- 각 활동은 처음 계산한 시점의 역치로 고정 — 과거 기록 덮어쓰기 금지 원칙 (memory `feedback-no-overwrite-history`) 과 같다
- 대가: Garmin 이 활동 원본을 나중에 고쳐도 (존 시간 재처리 등) 강도는 따라가지 않는다 → 필요하면 `--force`
- "처음 계산한 역치" = **activities 단계 시점의 프로필 값**. 일일 싱크는 activities 가 user_profile 보다 먼저라, 그 러닝이 Garmin LTHR 자동 감지를 일으켰다면 그 러닝 자신은 이전 LTHR 로 고정된다 (이전엔 다음 날 재싱크가 고쳤다). LTHR 은 경계 라벨 보정에만 쓰여 영향이 작다 — 필요하면 `--force`. 파워는 역치파워가 없으면 계산하지 않고 프로필 싱크 뒤 채우므로 해당 없음 (사전 리뷰 info 1)
