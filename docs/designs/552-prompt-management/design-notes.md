# 프롬프트 관리 디자인 노트 (#552)

시안: `preview.html` (상태 A ~ F). 스크린샷 `screenshots/desktop.png` · `mobile-375.png`.
**리포트 결과 문구 · 수치는 가상** (memory: 건강 데이터 public 노출 금지).

## 브리프

이 화면을 여는 이유는 셋 — **"지금 어떤 문구로 돌고 있나"**, **"언제 무엇을 바꿨고 결과가 어떻게 달라졌나"**, **"바꾸기 전에 안전한가"**. 편집기는 수단이고, 화면의 중심은 버전이 이어지는 흐름 (계보) 이다.

## 제약

#527 · #544 화면 언어 그대로 (h1 24px · 카드 12px · Geist / 코드 · 버전 · 시각 Geist Mono · 경고 amber · 오류 red · 액센트 녹색). 새 색은 **AI 제안 = violet-300 (배경 violet-500/16)** 하나 — 녹색 (사용 중 · 추가) · 빨강 (오류 · 삭제) · amber (경고 · 변수) 와 겹치지 않게. 편집기의 도구 이름은 blue-300 (문법 강조 전용).

## 결정

### 위치
`/settings/prompts` — 설정 상단 **프로필 · 프롬프트** 탭. 사이드바 "설정" 은 그대로 `/settings/profile`. 상세는 `/settings/prompts/[key]`, 탭 **편집 · 결과** (결과 탭은 M19-2).

### 목록 (A)
묶음 3개 (공통 · 리포트 · 운동 평가) · 카드: 이름 · 사용처 (언제 · 어디서 쓰이나) · 사용 중 vN (녹색 mono) · 출처 배지 · 초안 수 · 활성화 일자. 시스템 프롬프트는 전체 폭 — 모든 응답의 바탕이라는 위계.
**코드 기본값 갱신** (스펙 R2 · 웹에서 고친 키에 새 코드 기본값이 초안으로 들어옴) 은 페이지 상단 amber 안내 + 해당 카드 배지. "차이 보기" 는 상세의 C 로.

### 상세 · 편집 (B) + 버전 계보 — 이 화면의 강조
- 왼쪽 편집기: 줄 번호 · `{{변수}}` amber 하이라이트 · 도구 이름 blue · **오류는 해당 토큰에 물결 밑줄 + 아래 검증 목록에 행 번호**. 오류가 있으면 저장 버튼 둘 다 비활성 · 경고만 있으면 저장 가능.
- 상단 바에 쓸 수 있는 변수 목록 (키별).
- 하단: 변경 메모 + **초안 저장** / **저장하고 활성화**.
- 오른쪽 레일: 세로선으로 이어진 버전 노드. **노드 모양 = 출처** (빈 원 = 코드 기본값 · 흰 점 = 직접 수정 · 보라 점 = AI 제안 · 고리 = 되돌림), **녹색 고리 = 사용 중**, 보관 버전은 흐리게. 각 노드: 메모 · "vN 에서 고침/제안" · 결과 N건 · 시각 · 동작 (비교 체크 · 초안이면 활성화 · 시험 실행 / 보관이면 이 버전으로 되돌리기). 비교 체크 2개 → C.
- 모바일 (< 900px): 레일이 편집기 아래로.
- 시스템 프롬프트 (B′) 는 편집기 위 amber 안내 — 전 채널 즉시 적용 · 대화는 다음 질문부터 새 세션 · 프로필 등은 자동으로 뒤에 붙음.

### 버전 비교 (C)
줄 단위 diff — 양쪽 줄 번호 · `+` 녹색 / `−` 빨강 배경 · 같은 줄은 "같은 줄 N개" 로 접기 (앞뒤 2줄 문맥). 헤더에 두 버전 배지 · `+N −N`. 초안이 끼어 있으면 그 초안 활성화 버튼. 코드 기본값 갱신 비교에선 **"v5 를 v4 에 합쳐 고치기"** — 사용 중 버전 본문을 편집기에 열고 이 diff 를 옆에 둔 채 직접 반영 (자동 병합은 하지 않는다).

### 결과 (D · M19-2)
버전 필터 칩 (여러 개) · 왼쪽 목록 (날짜 · 버전 배지 · 첫 줄 요약) · 2개 선택 → 오른쪽 나란히 (마크다운 렌더). 기본 선택은 최신 결과 + 다른 버전의 최신 결과. "버전 정보 없음" 은 연결 전 결과. 운동 평가 키는 날짜 대신 활동 (날짜 · 거리).

### AI 개선안 (E · M19-3)
상세 헤더의 **AI 개선안 받기** (보라). 진행 중엔 스피너 + "CLI 쿼터 사용 · 최대 1분". 결과: 근거 목록 → 사용 중 버전 대비 diff → 검증 결과 → **초안으로 저장** / 버리기. "저장해도 바로 쓰이지 않는다" 를 명시.

### 시험 실행 (F · M19-3)
초안 노드의 "시험 실행" → 패널: 리포트 키는 "지금 시점 기준 · 리포트 목록에 저장 안 됨" 설명 + 실행, 운동 평가 키는 최근 활동 선택 (F′). 결과는 **같은 대상의 최근 실제 결과 (사용 중 버전)** 와 나란히. 아래 시험 기록 (시각 · 완료/실패 · 실패 사유). 실행 중엔 버튼 비활성 (동시 1건).

## 문구

- 상태: **사용 중** (active) · **초안** (draft) · 보관은 배지 없이 흐리게. 출처: **코드 기본값 · 직접 수정 · AI 제안 · 되돌림**.
- 동작 이름은 흐름 내내 같게: "활성화" → 토스트 "v5 를 사용합니다", "초안으로 저장" → "v6 초안을 저장했습니다", "이 버전으로 되돌리기" → "v3 를 v7 로 되돌렸습니다".
- 검증 오류는 무엇 · 어디 · 어떻게: "모르는 변수 {{x}} — 쓸 수 있는 변수는 위 세 개입니다 (15행)".

## 구현 메모

- 편집기 강조는 `textarea` + 같은 글꼴 · 줄 높이의 `pre` 오버레이 (스크롤 동기화) — 에디터 패키지 추가 없음. 줄 번호는 오버레이 쪽.
- 검증은 클라이언트에서 `validate.ts` (순수) 로 즉시, 저장 시 서버에서 재검증.
- 시안 캡처: 헤드리스 Chrome 최소 창 폭이 485px 이라 모바일은 `html,body{width:375px}` 를 주입해 찍었다.
