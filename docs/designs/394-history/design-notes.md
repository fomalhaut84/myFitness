# `/history` 브라우저 — 디자인 노트 (#394)

시안: `preview.html` (단일 파일 · 가짜 데이터 · 해시 라우팅 `#/2024` → `#/2024/03` → `#/2024/03/15`, `?metric=`).
브라우저로 바로 열면 된다. 하한 2020-06-16 · 오늘 2026-09-21 고정.

## 브리프

6년치 기록을 **연 → 월 → 일** 로 내려가며 읽는 화면. 사용자는 본인 1명, 러너. 이 화면의 일은 분석이 아니라
**"그때 어땠더라" 를 찾아가는 것** 이다 (분석은 #395 `/trends`). 그래서 주인공은 차트가 아니라 **달력** 이다.

## 제약 (선택이 아닌 전제)

기존 앱 안의 신규 페이지다. 컨테이너·텍스트 위계·보더는 `globals.css` 토큰을 **그대로 상속** 한다
(`--bg #0a0a0a` · `--card #161616` · `--border #262626` · `--dim/--sub/--text/--bright`). 서체도 앱의 Geist / Geist Mono.
수치를 mono 로 쓰는 것은 앱 전체의 기존 관례 (수면 단계 시간 · SpO2 판독값) 라 따른다.

자유도를 쓴 곳은 세 군데뿐이다: (1) 연 뷰의 형태 (2) 셀의 세 가지 상태 (3) 일 뷰의 구조.

## 토큰

### 지표 색 — 선택 지표가 화면의 색을 정한다

| 지표 | 색 | 근거 |
|---|---|---|
| 러닝 거리 | `#22c55e` | 앱 accent. 활동 = 초록은 lifestyle 히트맵과 같은 의미 |
| 걸음 | `#fbbf24` | |
| 수면 점수 | `#a78bfa` | `SleepScoreChart` 의 기존 바이올렛 |
| 안정시 심박 | `#f87171` | |
| 체중 | `#2dd4bf` | SpO2 의 sky `#38bdf8` 와 구별되는 teal |
| 러닝 횟수 · VO2max · 칼로리 밸런스 · 섭취 칼로리 | `#86efac` · `#fb923c` · `#e879f9` · `#f472b6` | 추가 지표 |

화면에는 **한 번에 한 지표 색만** 나온다 (선택기 점 · 선택 테두리 · 셀 강도 · 스트립 막대 · 오늘 링). 색은 장식이 아니라
"지금 무엇을 보고 있는가" 의 표시다. 색 강도는 5단계 `color-mix(지표색 14/26/40/56/74%, #161616)`.
구현 시 지표 색은 레지스트리가 아니라 `src/components/history/metric-colors.ts` 에 둔다 (lib 는 표시와 무관하게 유지).

### 강도 스케일

- 합계형 (러닝 km · 걸음): 0 ~ 뷰 범위 최댓값.
- 평균·최고형 (수면 · 심박 · 체중 · VO2max): 뷰 범위 **min ~ max 정규화**. 체중 71~73kg 을 0 기준으로 칠하면 전부 같은 색이 된다.
- 강도는 **크기** 이지 좋고 나쁨이 아니다 (심박은 낮을수록 좋지만 진하게 칠해지는 건 높은 날). 범례를 "낮음 → 높음" 으로 적어 오독을 막는다.
- **스펙과 다른 점 (승인 필요):** 이슈 본문은 "러닝 km 는 숫자+색 강도, 나머지는 숫자" 였다. 시안은 **모든 지표에 색 강도** 를 준다 —
  연 뷰 미니 달력은 숫자가 없어 색이 유일한 정보라 어차피 전 지표에 스케일이 필요하고, 월 뷰만 색을 빼면 같은 지표가 레벨마다 다르게 보인다.

### 셀의 세 상태 (결측 ≠ 0)

| 상태 | 표현 |
|---|---|
| 값 있음 | 지표색 강도 배경 + 숫자 |
| **0** (러닝 거리·횟수만 — 쉰 날) | `--card` 배경 + 가운뎃점. 칸은 있다 |
| **기록 없음** | 배경 없음 + 1px 윤곽 + "없음". **칸이 비어 있다** |
| 범위 밖 (미래 · 하한 이전) | 날짜만 흐리게, 링크 없음 |

0 은 "채워진 빈칸", 결측은 "뚫린 칸" — 워치 미착용일이 달력에서 구멍으로 보인다.

- **연 뷰 = 12개월 밀착 인화.** 월 카드에 숫자 하나만 두는 대신 **그 달의 실제 달력** 을 작게 넣는다. 1년이 한 화면에서
  "언제 많이 뛰었고 언제 비었나" 로 읽힌다. 이 화면의 가장 과감한 선택이고, 나머지는 조용하게 둔다.
  카드 하단 한 줄은 커버리지: 합계형 "18일 달림", 평균형 "7/31일 기록".
- **KPI 는 카드 7장이 아니라 한 줄의 판독값 띠.** 모바일에서는 가로 스크롤 한 줄 — 세로로 쌓으면 달력이 첫 화면 밖으로 밀린다 (초안에서 확인 후 수정).
- **월 그리드**: 모바일은 정사각 셀 (360px 에서 셀 약 44px — 7열 유지 확인), 데스크톱은 1.55:1 로 눕혀 스트립까지 한 화면에.
  걸음은 셀 안에서 `17.8k`, 러닝은 소수 1자리로 축약하고 정식 표기 (km 2자리) 는 `aria-label` · KPI · 일 뷰에.
- **일 뷰 = 하루의 장부.** 같은 모양의 카드 8장이 아니라 한 컨테이너 안의 8행 (왼쪽 제목 132px · 오른쪽 내용).
  기록 없는 섹션은 **한 줄로 접히고 배경이 한 단계 어둡다** — 숨기지 않되 (요구사항) 자리를 차지하지 않는다.
  심층 링크 ("수면 상세" · "영양 페이지") 는 제목 아래에, 레코드가 있을 때만.
- 정렬은 전부 좌측. 섹션 순서는 요구사항의 8개 고정 순서 — 번호는 붙이지 않는다 (순서가 절차가 아니다).

## 네비

- 브레드크럼이 곧 제목이다: `기록 › 2024 › 3월` 에서 마지막 조각이 h1. 상위 조각은 링크.
- 연 레벨은 이전/다음 대신 **연도 탭** (7개라 전부 보인다). 월·일은 이전/다음 + 네이티브 `<input type="month|date">` (`min`/`max` = 하한/오늘).
  `NutritionDateNav` 의 팝오버 picker 는 가져오지 않았다 — 네이티브 입력이 모바일에서 OS 달력을 바로 띄워 한 단계 짧다.
- 경계에서 이전/다음은 비활성. "올해 / 이번 달 / 오늘" 은 항상 오른쪽.
- 지표 선택은 기본 5 · 구분선 · 추가 4. 모바일은 가로 스크롤.

## 접근성 · 품질 바닥

셀은 전부 `<a>` + `aria-label="15일 6.00km"` · `:focus-visible` 링은 지표색 · 미니 달력은 `aria-hidden` (카드의 숫자·커버리지가 같은 정보) ·
색만으로 구분하지 않는다 (0 은 점, 결측은 "없음" 글자) · 모션 없음.

## 위험

- **SpO2**: 일 뷰 수면 행의 "최저 SpO2" 는 값만. 색·경고 없음 (memory `project_user_spo2_baseline` — 83~88 이 이 사용자의 정상).
- **`<input type="month">`** 는 데스크톱 Safari/Firefox 에서 텍스트 입력으로 떨어진다. 구현 시 형식 검증 후 이동, 실패는 무시 (이전/다음·브레드크럼으로 충분).
- 미니 달력은 월당 최대 37칸 × 12 = DOM 440개 남짓 — 문제 없는 규모.
- 색 강도가 뷰 범위 상대값이라 **달마다 같은 색이 다른 값** 이다. 범례에 절대값을 넣을지는 구현 중 판단 (시안은 "낮음 → 높음").

## 사용자 확인이 필요한 결정

1. 월 그리드에서 **모든 지표에 색 강도** (이슈 본문은 러닝 km 만) — 위 "강도 스케일".
2. **식단 캘린더 흡수** — "섭취 칼로리" 를 추가 지표로 (스펙 §4.2).
3. picker 를 팝오버 대신 **네이티브 입력 직접 노출**.
4. 일 뷰를 카드 8장 대신 **한 컨테이너의 8행**.
