# 하이라이트 — 디자인 노트 (#396)

시안: `preview.html` (단일 파일 · 해시 라우팅). 시계열 데이터는 가짜(시드 난수), **레이스 14건은 프로덕션 실제 목록** (2026-09-22 조회), 지표 변경 · 플랜 · 커버리지의 혈압/식단 시작일은 가짜.
하한 2020-06-16 · 오늘 2026-09-21 고정. 진입: `#view=series` (마커) · `#view=series&unit=year&range=all` (겹침 라벨) · `#view=records` · `#page=history&cov=open` · `#view=series&marks=0`.

## 브리프

#394 는 찾아가는 화면, #395 는 비교하는 화면이다. 둘 다 **값** 만 보여준다. 이 이슈는 값에 **원인** 을 붙이고 (마커), **최고점** 을 날짜와 함께 꺼내고 (개인 기록), 차트에서 **그 날로** 간다 (포인트 클릭).
새 화면이 아니라 두 화면에 얹는 것이므로 새 디자인 언어를 만들지 않는다 — 토큰 · 서체 · 지표 색 · pill · 판독값 띠 · 장부 형태 전부 #394/#395 그대로.

## 제약

- 한 화면에 한 지표 색 (#394). **마커는 지표가 아니므로 무채색이다** — 이것이 이 시안의 핵심 제약이자 결정.
- 불완전한 데이터 3구분 (#395) 은 손대지 않는다. 마커가 그 위에 얹혀도 저커버리지 막대 · 점선 막대는 그대로 읽혀야 한다.
- 모션 없음 · 색만으로 구분 금지 · 차트는 `role="img"` + 글자 대응물.

## 결정

### 마커 — 무채색 3단, 형태로 종류를 가른다

| 종류 | 표현 | 이유 |
|---|---|---|
| 레이스 | **실선 세로줄 (`#e5e5e5`, 1.5px)** + 위쪽 `R` | 가장 드물고 (6년 14건) 가장 "사건" 이라 가장 밝다 |
| maxHR · LTHR 변경 | 점선 세로줄 (`#737373`, 1px) | 설정 변경이라 한 단계 뒤로. 형태(점선)로도 구분 |
| 트레이닝 플랜 기간 | 흰색 6% 밴드 | 점이 아니라 기간. 데이터 뒤에 깔린다 |

- 선은 데이터 **위에**, 밴드는 데이터 **아래에** 그린다. 밴드가 위에 오면 막대 색이 탁해진다.
- **같은 버킷에 여럿이면 선 하나 + 라벨 `R+1` / `×2`.** 연 단위에서 2023·2024 는 레이스 3건씩 — 선 3개를 겹치면 두꺼운 선 하나로 보이고 정보가 없다. 툴팁과 목록이 개별 건을 가진다.
- **연 단위에서는 플랜 밴드를 그리지 않는다.** 6주 플랜이 한 해 전체를 덮어 "2023년 내내 플랜" 으로 읽힌다. 목록에는 남는다 (범례 문구 `플랜 기간은 연 단위에서 목록에만`).
- 마커 라벨은 모바일에서 숨긴다 (76개 월 버킷 폭에 글자가 안 들어간다). 목록이 대신한다.
- 토글은 지표 pill 과 같은 형태지만 색 점 대신 마커 글리프. 켜짐 상태는 지표색이 아니라 밝은 테두리 — 마커는 무채색이라는 규칙을 컨트롤에서도 지킨다. URL `marks=0`.

### 이 기간의 이벤트 — 차트의 글자 대응물

차트 아래 목록. 날짜 (mono) · 종류 (글리프 + 글자) · 내용 · 링크. 종류 배지에 색을 넣지 않고 차트와 같은 글리프를 쓴다 — 범례가 곧 배지.
레이스는 `이름 · 거리 · 페이스 · 시간`, 지표 변경은 `LTHR 160 → 158`, 플랜은 `하프 플랜 6주 · 주 4회 ~ 끝날`. 링크 문구는 목적지를 말한다: `그 날 보기` / `플랜 보기` / `프로필 보기`.
최신순 · 30건 넘으면 `외 N건`. 빈 상태는 무엇을 하면 채워지는지 말한다 ("Garmin 에서 활동을 레이스로 표시하거나 …").

### 개인 기록 — 하루의 장부와 같은 형태

카드 8장이 아니라 **한 컨테이너 8행** (#394 일 뷰의 장부). 왼쪽 제목 132px · 값 mono 17px · 오른쪽 **날짜가 링크**.
사용자의 질문은 "얼마" 보다 "**언제**" 다 — 날짜를 캡션이 아니라 값과 같은 급의 mono 로 오른쪽 끝에 둔다.
- 러닝 기록의 값은 **소요 시간** 이 먼저 (`1:41:52`), 페이스 · 거리는 부제. 하프 기록을 "4:49/km" 로 기억하는 사람은 없다.
- 레이스 활동이면 `레이스` 배지 (윤곽 pill, 무채색). 실측: 10K · 하프 최고는 레이스일 가능성이 높다.
- 풀은 기록이 없다 → 행은 남기고 (`40km 이상 달린 기록이 없습니다`) 배경 한 단계 어둡게 — 일 뷰의 "기록 없는 섹션" 과 같은 처리. 행을 빼면 "풀은 원래 없는 항목" 이 된다.
- VO2max · RHR 은 "처음 도달한 날" — 캡션으로 규칙을 밝힌다 (plateau 는 MCP 몫).
- 아래에 **레이스 표** (14건 · 최신순). 이름은 Garmin 활동 이름 그대로 (`달리기` · `10km 러닝` 도 그대로 — 이름을 지어내지 않는다). 모바일은 표가 가로 스크롤 (이름 열 최소 170px 로 글자 단위 줄바꿈 방지).
- 이 뷰에서 지표 pill · 단위 · 기간 컨트롤은 숨긴다 — 지표와 무관하다 (#395 "뷰에 의미 없으면 숨긴다").

### 포인트 클릭

막대 · 점이 `<a>` 다. 툴팁 마지막 줄 `클릭 → 월 뷰` / `연 뷰`. lede 문장에도 한 번 (`막대나 점을 누르면 그 달의 기록으로 갑니다`) — 발견 가능성은 툴팁만으로 부족하다.
호버는 밝기 25% — 지표색을 바꾸지 않는다.

### 커버리지 띠 — 접힌 한 줄, 펼치면 소스별 막대

`/history` 연 뷰의 지표 pill 아래 · KPI 위. 기본은 **한 줄** (`2020.06 ~ 2026.09 · 활동 2,332건 · 일간 요약 2,286일 · …`) — 매번 보는 정보가 아니라서 6~8행을 항상 펼쳐 두지 않는다. 네이티브 `<details>` (JS 없음).
펼치면 소스별 가로 막대 (하한 → 오늘 축, `#8f8f8f` 단색 — 지표 색 없음). **실데이터에서는 5개 소스가 전부 2020-06 시작이라 막대가 똑같다** → 범위가 실제로 다른 소스 (야간 HRV 2026-04 · 혈압 · 식단) 를 넣어야 띠가 정보를 가진다. 스펙 F20 의 "혈압 제외" 는 이 관찰로 뒤집는다 (구현 시 반영).

## 구현 시 시안과 달라지는 것

- **포인트는 `<a>` 가 아니라 SVG `onClick`** (Recharts 막대 · 점). 차트가 `role="img"` 라 접근 가능한 경로는 판독값 · 이벤트 목록 링크 — YoY 뷰는 후속 이슈.
- 차트는 Recharts — 마커는 `ReferenceLine` (`x=버킷 키`, 카테고리 축 · 연 경계선과 같은 방식) + `label`, 밴드는 `ReferenceArea`. 클릭은 `Bar`/`Line` `onClick` + `router.push`.
- 툴팁의 이벤트 문장은 시안에 `<title>` 로만 있다.
- 시안의 SVG 는 viewBox 축소라 모바일에서 글자가 작다 — 구현은 고정 높이 (220/300).
- YoY · 계절성 뷰는 #395 시안 그대로 — 달라지는 것은 점 클릭뿐이라 이 시안에 다시 그리지 않았다.

## 접근성 · 품질 바닥

포인트 · 날짜 · 이벤트 링크는 전부 `<a>` · 마커 토글은 `role="switch"` + `aria-checked` · 차트 `role="img"` + 목록/장부가 같은 정보를 글자로 · 무채색 마커는 실선/점선/면으로 구분 · 모션 없음 · 360px 에서 페이지 가로 넘침 없음 (CDP 측정 `scrollWidth = 360`).
