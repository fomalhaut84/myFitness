# `/insights` 분석 — 디자인 노트 (#397)

시안: `preview.html` (단일 파일 · 가짜 데이터 — 시드 난수에 연도별 경향을 심어 둠: 해마다 페이스 ↑ 심박 ↓ · 여름 느림 · 2023-10~2024-04 피크 · 존 분포 2024-12 부터 · 주간 km → 다음 주 RHR 약한 양의 지연). 하한 2020-06-16 · 오늘 2026-09-21 고정. 범례 버튼은 연도 토글.

## 브리프

`/history` 는 찾아가고, `/trends` 는 지표 하나를 비교한다. `/insights` 는 **두 값의 관계** 를 본다 — "같은 페이스를 더 낮은 심박으로?", "여름이 페이스를 얼마나 깎나?", "강도 배분이 달라졌나?", "많이 뛴 다음 주에 심박이 오르나?". 사용자는 본인 1명, 러닝 2,156건 · 6년치.
차트가 주인공이 아니다. **제목이 질문이고, 오른쪽 큰 숫자가 답**이다. 차트는 그 답이 어디서 왔는지 보여 주는 근거다.

## 제약

#394/#395 와 같은 앱 — 토큰 · 서체 · 카드 · 판독값 띠 그대로. 자유도를 쓴 곳은 (1) 패널의 답 구조 (2) 산점도의 연도 색 (3) 존 스택의 범주 색.

## 결정

### 패널 = 질문 → 차트 → 답 (큰 숫자 하나 + 근거 표)

한 패널에 요약 카드 3장을 늘어놓지 않는다. **답이 되는 숫자 하나** (`−9 bpm` · `+19 초/km` · `68% ← 65%` · `r +0.07`) 를 26px mono 로 왼쪽에, 그 근거 (연도별 · 온도 구간별 · 4분위) 를 작은 표로 오른쪽에. 표는 `CompareTable` 톤 (헤더 회색 · 값 mono · `n=` 은 흐리게).
- 표의 빈 칸 (5건 미만) 은 `—` — 적은 표본으로 만든 평균을 숫자로 내지 않는다.
- 각 패널 아래 한 줄 `foot`: 계산 규칙을 사용자 말로 ("평균이 아니라 중앙값 — 극단값에 덜 흔들립니다").

### 산점도 — 올해만 색, 과거는 회색 사다리 (YoY 규칙)

2,000개 점에 연도별 색 7개를 주면 무지개다. YoY 와 같은 규칙 — **올해 = 심박 색 `#f87171`, 과거 = 최근일수록 밝은 회색**. 연도 토글로 한 해씩 켜고 끈다.
- 점은 r 2.2 · 불투명도 0.7 — 겹침이 밀도로 보인다 (겹치는 곳이 밝아진다).
- 레이스는 속 빈 점 (#395 의 "속 빈 점" 은 저커버리지였다 — 여기서는 저커버리지 개념이 없어 충돌하지 않는다. 범례에 명시).
- **페이스 축은 빠를수록 오른쪽/위** — "오른쪽 아래로 내려가면 좋아진 것" 이 되게 (효율 패널: 오른쪽 = 빠름, 아래 = 낮은 심박).

### 기온 패널 — 색은 연도가 아니라 습도

이 패널의 질문은 "언제" 가 아니라 "얼마나 더운가" 라서 연도 색을 쓰지 않는다. 습도 3단을 **단일 색조 (`#fbbf24` 걸음 색 계열) 램프** 로 — 어두운 것이 건조, 밝은 것이 습함. 범례 3개.
- 실데이터 `weatherTempC` 는 소수라 시안처럼 세로 줄무늬 (정수 기온) 가 생기지 않는다.

### 존 스택 — 범주 색은 앱의 기존 5색

"한 화면 한 지표 색" 의 예외. 존 1~5 는 활동 상세에서 이미 회색 · 초록 · 파랑 · 주황 · 빨강으로 굳어진 범주라 여기서 다른 색을 주면 같은 것이 다르게 보인다. 100% 스택이라 세로축은 비율.
- 존 없는 달은 **점선 윤곽의 빈 칸** (#394 의 "기록 없음 = 뚫린 칸"), 존 있는 러닝이 절반 미만인 달은 흐리게 (#395 저커버리지), 이번 달은 점선 막대 (#395 미완결).
- 캡션에 시작일 (`존 분포는 2024-12 부터`) — 하드코딩이 아니라 데이터에서. 백필로 앞당겨지면 캡션도 따라간다.

### 지연 상관 — r 세 개를 나란히

"다음 주" 만 보여 주면 우연인지 모른다. **같은 주 · 1주 뒤 · 2주 뒤** 의 r 을 나란히 두어 지연 효과가 있는지 비교하게 한다. 문구는 셋뿐 — 관계 없음 (< 0.1) · 약한 관계 · 관계 있음 (≥ 0.3). 통계 검정이 아님을 foot 에 적는다.
4분위 표는 r 을 읽지 못해도 "많이 뛴 주 다음 주가 몇 bpm 높나" 를 숫자로 보여 준다.

### 컨트롤을 두지 않는다

기간은 전체 고정 — 산점도는 6년이 한 번에 있어야 연도 차이가 보인다. 지표 선택도 없다 (패널마다 필드가 정해져 있다). 남는 컨트롤은 연도 토글뿐이고, 그것도 패널마다 독립.

## 구현 시 시안과 달라지는 것

- 차트는 Recharts `ScatterChart` · `BarChart stackOffset="expand"`. 산점도 축은 nice tick, 시안의 7등분 눈금은 시안 한정.
- 차트 높이 고정 (데스크톱 320 · 모바일 220). 시안 SVG 는 viewBox 축소라 폰에서 글자가 작다 — 구현에서는 해당 없음.
- 툴팁 (날짜 · 값 · `클릭 → 활동`) 은 시안에 `<title>` 로만. 점 클릭 → 활동 상세 (`/activities/<id>`).
- 표는 모바일에서 가로 스크롤 (시안과 동일).

## 접근성 · 품질 바닥

연도 토글 `aria-pressed` · 차트 `role="img"` + 표 · 판독값이 같은 정보를 글자로 · 색만으로 구분하지 않음 (레이스 = 속 빈 점 · 저커버리지 = 흐림 + 범례 · 미완결 = 점선) · 모션 없음 · 360px 가로 넘침 없음 (CDP 측정 `scrollWidth = 360`).

## 사용자 확인이 필요한 결정

1. **답 구조**: 큰 숫자 하나 + 근거 표 (요약 카드 3장 아님).
2. **효율 패널 기준 구간** 5'00"~5'30"/km — 사용자 평균 페이스 근처의 30초 폭. 실데이터 보고 조정 가능 (상수 1곳).
3. **기온 패널은 연도 색 대신 습도 색.**
4. **존 스택은 활동 상세의 5색 그대로** ("한 화면 한 지표 색" 예외).
5. **기간 컨트롤 없음** (전체 고정).
