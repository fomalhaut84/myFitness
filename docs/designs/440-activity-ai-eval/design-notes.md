# AI 평가 — 활동 상세 결과 블록 디자인 노트 (#440)

시안: `preview.html` (단일 파일 · 상태 5개 A~E). 스크린샷 `screenshots/desktop.png` · `mobile-360.png`.

## 브리프

활동 상세 맨 아래, 지금은 버튼 하나 ("🤖 AI 평가 요청") 와 결과 카드 (prose) 뿐인 자리. 결과가 6개 지표 3줄에서 **8개 섹션 + 종합**으로 길어진다. 읽는 사람의 질문은 두 가지 — "무엇을 근거로 봤나" 와 "그래서 결론이 뭔가". 전자는 상단 칩, 후자는 하단 종합이 답한다.

## 제약

활동 상세의 기존 언어 그대로 — 제목은 카드 밖 `h2`, 카드는 12px 라운드 · 1px 보더, 라벨은 11px dim uppercase tracking, 수치 · 메타는 Geist Mono. 버튼은 기존 것과 동일. 새 색 없음 — 액센트 (`#22c55e`) 는 종합 구분선과 "다음 러닝" 라벨 두 곳에만.

## 결정

### 근거 칩 — 모델이 아니라 서버가 말한다

카드 상단 한 줄에 **서버 응답의 `sections`** 를 칩으로 (모델 응답을 파싱하지 않는다). 생략된 섹션 (`omitted`, 예: 스플릿 API 실패) 은 점선 흐린 칩 `km 스플릿 · 조회 실패` — 왜 그 얘기가 없는지가 보인다. 데이터가 원래 없어 빠진 섹션은 칩도 없다 (상세 페이지가 그 섹션을 안 그리는 것과 같은 규칙).

### 본문은 모델 마크다운 그대로, `h3` 를 라벨 급으로

모델은 `### 제목` + 1~2문장 을 낸다. 클라이언트는 marked + DOMPurify (기존) 로 렌더하고 `h3` 를 카드 라벨과 같은 11px dim uppercase 로 내린다 — 섹션 구분은 생기되 카드 안에 작은 제목이 8개 서 있는 느낌은 피한다. 강조 (`**`) 만 밝은 글자.

### 종합 — 유일하게 밝은 문단

`### 종합` 은 왼쪽 1px 액센트 선 + 밝은 글자. 색 채움 · 배경 박스 없음. "다음 러닝" 한 줄은 종합 안에서 액센트 라벨로 — 모델이 `**다음 러닝**` 으로 시작하도록 프롬프트가 지시하고 클라이언트는 `종합` 헤딩 이후를 `.summary` 로 감싼다 (헤딩 텍스트 매칭 1곳 · 실패해도 일반 문단으로 보일 뿐).

### 상태 4 + 요약 모드

| 상태 | 표시 |
|---|---|
| A 대기 | 버튼 하나 (현행) |
| B 분석 중 | 카드 한 줄: 점 3개 펄스 + "상세 지표 N개 섹션을 근거로 분석하고 있어요" + 경과 초 (mono) + "보통 30~90초". N 은 클라이언트가 모른다 → 실제 구현은 "상세 지표를 근거로" 로 둔다 |
